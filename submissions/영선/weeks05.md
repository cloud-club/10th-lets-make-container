### namespace·veth·bridge·route·forwarding·NAT는 패킷 경로에서 각각 어떤 역할을 하나요?
- Network namespace: 컨테이너마다 네트워크 환경을 분리합니다.
- veth: 서로 다른 네트워크 공간을 연결하는 가상 케이블 역할을 합니다.
- bridge: 여러 가상 네트워크 인터페이스를 연결하는 가상 스위치입니다.
- route: 패킷을 어느 경로로 보낼지 결정합니다.
- forwarding: 호스트가 자신에게 도착한 패킷을 다른 네트워크로 전달하도록 합니다.
- NAT: 패킷의 IP 주소 등을 변환해 컨테이너가 외부 네트워크와 통신할 수 있게 합니다.

### NAT만 제거하면 호스트와의 통신과 외부 통신은 어떻게 달라질까요?
호스트와 통신: 10.200.0.1과 10.200.0.2는 같은 네트워크에 있으므로 NAT 없이도 통신할 수 있습니다.

외부와 통신: 일반적으로 실패합니다. 출발지 IP 10.200.0.2가 사설 IP라 외부에서 응답을 돌려보낼 경로가 없기 때문입니다.

### 호스트에서는 10.200.0.2로 직접 접근할 수 있는데, VM 외부에서는 왜 추가 설정이 필요할까요?
호스트에는 10.200.0.0/24 네트워크가 직접 연결되어 있어 10.200.0.2로 바로 패킷을 보낼 수 있습니다.
하지만 VM 외부에서는 이 주소를 직접 찾아갈 수 없습니다. 10.200.0.2는 사설 IP이고, 외부 네트워크에서 VM 내부까지 들어오는 경로도 기본적으로 설정되어 있지 않기 때문입니다.
따라서 외부에서 접근하려면 보통 호스트의 포트로 들어온 요청을 10.200.0.2:80으로 전달하는 DNAT와 forwarding 허용 규칙이 필요합니다

### 별도의 network namespace를 쓰는 컨테이너 안의 웹 서버가 127.0.0.1에서만 listen하면 호스트에서 접근할 수 있을까요? 0.0.0.0에서 listen하면 무엇이 달라지나요?
127.0.0.1 전체: 내 컴퓨터 자신을 가리키는 주소입니다. 네트워크를 통해 외부로 나가지 않고 자기 자신에게 통신합니다.

127.0.0.1에서 listen: 호스트에서 접근할 수 없습니다. 컨테이너의 127.0.0.1은 컨테이너 자신의 loopback 주소이기 때문입니다.

0.0.0.0: 서버가 특정 IP 하나가 아니라, 해당 환경의 모든 IPv4 네트워크 인터페이스에서 요청을 받겠다는 의미입니다.

0.0.0.0에서 listen: 컨테이너의 모든 IPv4 인터페이스에서 연결을 받습니다. 따라서 호스트에서 10.200.0.2:80으로 접근할 수 있습니다.
