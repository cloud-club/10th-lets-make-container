## 1.namespace·veth·bridge·route·forwarding·NAT는 패킷 경로에서 각각 어떤 역할을 하나요?
Network namespace는 네트워크 인터페이스, IP 주소, 라우팅 테이블 등의 네트워크 환경을 격리한다. veth pair는 서로 다른 namespace 사이를 연결하는 가상 네트워크 인터페이스 쌍이며, bridge는 MAC 주소를 기반으로 여러 인터페이스 간 프레임을 전달하는 가상 스위치다.

Routing은 목적지 IP에 맞는 전달 경로를 결정하고, IP forwarding은 호스트가 수신한 패킷을 다른 네트워크로 중계할 수 있도록 한다. NAT는 SNAT를 통한 출발지 주소 변경과 DNAT를 통한 목적지 주소 변경을 수행한다.

## 2.NAT만 제거하면 호스트와의 통신과 외부 통신은 어떻게 달라질까요?
NAT 란 것은 NAT는 내 주소(출발지)변경 (SNAT) 뿐 아니라 상대방 주소(목적지) (DNAT)도 변경할 수 있다. 만약 이런 nat 을 없앤다면 같은 서브넷의 컨테이너 간 통신과 컨테이너-호스트 통신은 일반적으로 정상 작동하지만 외부 통신이 힘들어짐

## 3.호스트에서는 10.200.0.2로 직접 접근할 수 있는데, VM 외부에서는 왜 추가 설정이 필요할까요?

호스트 VM은 컨테이너 네트워크에 직접 연결되어 있으므로 10.200.0.2에 접근할 수 있다. 반면 VM 외부에서는 10.200.0.0/24 네트워크가 어디에 있는지 알 수 없으므로 별도의 라우팅 설정이 필요하다.

이를 해결하려면 VM을 다음 홉으로 지정하는 경로와 IP forwarding을 설정하거나, NAT 기반 포트 포워딩을 사용해야 한다. 방화벽 설정도 해당 통신을 허용해야 한다.

## 4.별도의 network namespace를 쓰는 컨테이너 안의 웹 서버가 127.0.0.1에서만 listen하면 호스트에서 접근할 수 있을까요? 0.0.0.0에서 listen하면 무엇이 달라지나요?
컨테이너가 별도의 network namespace를 사용하는 경우, 127.0.0.1은 컨테이너 자신의 loopback 주소다. 따라서 웹 서버가 127.0.0.1에서만 listen하면 호스트에서 컨테이너 IP로 접근할 수 없다.

반면 0.0.0.0에서 listen하면 컨테이너의 모든 로컬 IPv4 인터페이스에서 연결을 받을 수 있으므로, 네트워크 경로와 방화벽이 허용된다면 호스트에서 컨테이너 IP를 통해 접근할 수 있다.
