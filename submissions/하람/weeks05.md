### 1. namespace·veth·bridge·route·forwarding·NAT는 패킷 경로에서 각각 어떤 역할을 하나요?

namespace는 호스트와 컨테이너 내부의 네트워크를 분리한다.

route는 패킷을 컨테이너 내부에서 외부로 보내기 위해 gateway로 가는 길을 알려준다. 

veth는 가상 이더넷 선으로 컨테이너 namespace와 host bridge를 연결한다.

패킷이 bridge에 도착하면 forwarding을 통해 외부와 연결된 네트워크 인터페이스로 전달된다.

NAT는 외부로 패킷을 내보내기 전에 private ip 주소를 호스트의 ip 주소로 변환한다.

### 2. NAT만 제거하면 호스트와의 통신과 외부 통신은 어떻게 달라질까요?

호스트는 bridge, 가상 이더넷선으로 직접 연결된 같은 서브넷이라서 통신이 가능하다.

외부 통신은 불가능하다. private ip는 public internet 망에서 라우팅이 불가능하기 때문이다.

### 3. 호스트에서는 `10.200.0.2`로 직접 접근할 수 있는데, VM 외부에서는 왜 추가 설정이 필요할까요?

외부에서는 private ip를 알 수 없기 때문에, 외부에서 들어가기 위해서는 VM의 public ip를 private ip로 변환해 주는 DNAT 설정이 필요하다.

### 4. 별도의 network namespace를 쓰는 컨테이너 안의 웹 서버가 `127.0.0.1`에서만 listen하면 호스트에서 접근할 수 있을까요? `0.0.0.0`에서 listen하면 무엇이 달라지나요?

`127.0.0.1` 로 listen하면 호스트에 접근할 수 없다. 루프백 인터페이스(`127.0.0.1`)는 격리된 namespace 내부에서만 접근할 수 있다.

`0.0.0.0` 은 ‘지정된 주소 없음’, 즉 모든 주소를 의미→ 내 컴퓨터에 연결된 모든 IP 주소(`10.200.0.2`)를 의미한다. eth0(`10.200.0.2`)를 통해서 접속을 받아들인다. 그래서 `10.200.0.2`를 통해서 접근할 수 있다.
