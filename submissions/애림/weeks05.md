# 5주차 심화 질문 정리

## 1. namespace·veth·bridge·route·forwarding·NAT는 패킷 경로에서 각각 어떤 역할을 하나요?

- **network namespace**: 네트워크 인터페이스, IP, route 등을 격리한다.
- **veth**: 서로 다른 namespace를 연결하는 가상 케이블 역할을 한다.
- **bridge**: 여러 네트워크 인터페이스를 연결하는 가상 스위치 역할을 한다.
- **route**: 패킷을 어느 곳으로 보낼지 결정한다.
- **forwarding**: 호스트가 자신에게 도착한 패킷을 다른 네트워크로 전달하도록 한다.
- **NAT**: 외부로 나갈 때 출발지 IP를 호스트의 IP로 변환한다.

### 정리

> namespace는 네트워크를 격리하고, veth와 bridge는 연결하고, route는 경로를 정하고, forwarding은 패킷을 전달하고, NAT는 출발지 주소를 바꿔준다.

## 2. NAT만 제거하면 호스트와의 통신과 외부 통신은 어떻게 달라질까요?

- **호스트와는 통신할 수 있다.**
- **외부 통신은 정상적으로 이루어지기 어렵다.**

예를 들어 chroot 셸에서:

```bash
ping -c 1 10.200.0.1
```

은 같은 `10.200.0.0/24` 네트워크 안에서 통신하기 때문에 NAT가 필요하지 않다.

하지만 외부 네트워크로 나갈 때는 `10.200.0.2`라는 사설 IP를 그대로 가지고 나가기 때문에 외부에서 응답을 돌려보내기 어렵다.

### 정리

> NAT가 없어도 같은 네트워크에 있는 호스트와는 통신할 수 있지만, 외부 통신은 정상적으로 이루어지지 않는다.

## 3. 호스트에서는 10.200.0.2로 직접 접근할 수 있는데, VM 외부에서는 왜 추가 설정이 필요할까요?

`10.200.0.2`는 VM 내부의 사설 IP이기 때문에 VM 외부에서는 직접 접근할 수 없다.

호스트와 `ns-study`는 `10.200.0.0/24` 네트워크를 통해 직접 연결되어 있기 때문에:

```text
호스트 → 10.200.0.2
```

로 바로 접근할 수 있다.

하지만 VM 외부에서는:

```text
외부 → VM → 10.200.0.2
```

처럼 중간에서 전달이 필요하다.

따라서 외부에서 접근하려면 호스트의 주소와 포트를 받아서 `10.200.0.2`로 전달하는 **DNAT 같은 추가 설정**이 필요하다.

## 4. 별도의 network namespace를 쓰는 컨테이너 안의 웹 서버가 127.0.0.1에서만 listen하면 호스트에서 접근할 수 있을까요? 0.0.0.0에서 listen하면 무엇이 달라지나요?

### 127.0.0.1

`127.0.0.1`은 **현재 network namespace의 자기 자신**을 의미한다.

따라서 웹 서버가:

```text
127.0.0.1:80
```

에서만 listen하면 해당 namespace 내부에서만 접근할 수 있다.

예를 들어 `ns-study` 안에서:

```bash
curl 127.0.0.1
```

하면 웹 서버에 접속할 수 있지만, 호스트에서:

```bash
curl 127.0.0.1
```

하면 호스트 자신의 `127.0.0.1`에 접속하게 된다.

즉, 두 `127.0.0.1`은 서로 다른 network namespace에 속한다.

```text
호스트
└── ns-study
     ├── 127.0.0.1  ← ns-study 자기 자신
     └── 10.200.0.2 ← ns-study의 네트워크 주소

호스트                         ns-study
127.0.0.1                     127.0.0.1
   │                              │
   ▼                              ▼
호스트 자신                    ns-study 자신
```

따라서 호스트의 `127.0.0.1`과 `ns-study`의 `127.0.0.1`은 서로 다른 network namespace에 존재한다.

### 0.0.0.0

웹 서버가:

```text
0.0.0.0:80
```

으로 listen하면 해당 namespace의 모든 네트워크 인터페이스에서 들어오는 연결을 받을 수 있다.

따라서 `ns-study`의 `eth0` 주소인:

```text
10.200.0.2:80
```

을 통해 호스트에서 접근할 수 있다.

### 핵심 정리

> **127.0.0.1 = 현재 namespace의 자기 자신**
>
> **0.0.0.0 = 현재 namespace의 모든 네트워크 인터페이스에서 연결 받기**

## 추가자료: DNAT

**DNAT(Destination NAT)**는 들어오는 패킷의 **목적지 주소를 다른 주소로 변경해서 전달하는 것**이다.

예를 들어 외부에서 호스트의 특정 포트로 접속하면:

```text
외부
  │
  │ 호스트:8080
  ▼
호스트
  │
  │ DNAT
  ▼
ns-study
10.200.0.2:80
```

처럼 호스트로 들어온 연결을 `ns-study`의 `10.200.0.2:80`으로 전달할 수 있다.

### SNAT와 DNAT 차이

- **SNAT / MASQUERADE**: 외부로 나갈 때 **출발지 주소**를 변경한다.
- **DNAT**: 외부에서 들어올 때 **목적지 주소**를 변경한다.

> **SNAT = 나갈 때 주소 변경**
>
> **DNAT = 들어올 때 목적지 변경**
